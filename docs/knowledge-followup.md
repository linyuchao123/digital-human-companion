# 心理知识多轮追问

支持“这个练习怎么做”“再详细解释一下”“能举个例子吗”等短、完整的追问。只有最近连续用户/助手消息对内存在心理话题时，才把该用户原话与当前追问合并用于重新检索。最多回看3个消息对；用户话题上限320字符、当前追问上限160字符，超长话题不截断猜测。

不把助手正文、旧知识候选、来源卡片或会话摘要当作检索事实，不新增长期记忆或外部分类调用。实际回复模型与历史记录中的本轮用户文字仍保持原样，不用改写后的查询冒充用户输入。前文没有明确方法或指代多个方法时，模型收到先澄清、不要猜测的提示；提示不能保证所有生成回复都正确澄清。

任何中间话题切换、非连续消息角色、倾诉偏好、危机、遗忘、活动或天气/搜索请求都会终止回溯。“然后呢”“明天呢”等含义不明的短句不自动继承心理话题。当前查询的原工具优先级不变。

每轮重新初始化检索状态，防止可选LangGraph检查点保留上一轮的失败或空结果提示。追问上下文仅来自调用方传入的当前会话历史，不放到全局变量；开发者路由事件只增加 `knowledge_context_used` 布尔值，不公开用户原话或组合查询。

## 快捷追问入口

有心理知识参考的最新回复下增加“继续解释”“举个例子”“具体怎么做”。点击只填入输入框，不自动发送，可修改后自行确认。已有草稿不覆盖；旧回复或正在生成时不填入，并用可访问的状态文本说明原因。按钮使用固定问题，不执行知识正文里的内容，不改变音频播报内容。

`node tests/knowledge_followup_ui.cjs` 用模拟DOM验证来源条件、按钮、草稿保护、旧话题和忙碌状态；这不是实际浏览器视觉与听感验收。

## 断线时保留文字草稿

文字发送先确认WebSocket处于OPEN且浏览器发送调用没有抛出异常，再清空草稿和展示用户气泡；连接未就绪、断开或同步发送异常时保持原草稿、显示可访问错误提示，不假装已发送，也不自动重发。重新连接后由用户明确再次发送。语音录制和播报链路不改。

`node tests/text_send_reliability.cjs` 覆盖连接各状态、发送抛错、空草稿、成功提交以及明确重试。浏览器接受发送不等于服务器已收到或模型已处理；这里没有实现服务器回执、跨刷新持久草稿或断线自动恢复。

# 逐项优化进度

微信、QQ 真实接入暂缓，现有配置接口保留。个性化活动推荐继续暂停。

1. 2D 数字人：已将回复动作从固定 200ms 延迟改为实际语音播放启动时触发；支持无语音直接动作、流式首片段同步和取消防重放。待用户视觉验收，以及长语音过程的动作编排。
   - 播放异常紧急修复：口型改在 SDK `beforeModelUpdate` 事件中写入，避免被原生动作覆盖；增加静音阈值并降低音量映射增益。暂时禁用裸 PCM 流式路径，使用完整音频解码保证连续性；云端音色失败不再静默切换浏览器音色。延迟可能增加，需真实试听验收后恢复低延迟方案。
   - 后续低延迟修复：已按厂商官方 Qwen-TTS 说明确认 24kHz、16bit、单声道、小端 PCM，真实接口测试首包 0.556 秒、生成耗时 1.222 秒（单次测试，不代表稳定 SLA）。恢复流式，首段缓冲 320ms 音频、续段聚合 160ms，缓冲耗尽后留 200ms 恢复余量；正常衔接沿音频时钟，不人为逐段加间隙。保留最终绘制前口型覆盖与不静默换音色。需用户浏览器试听验收。
2. 大模型：下一阶段检查流式文本、首句语音联动、超时提示和长上下文管理，避免仅前端模拟打字。
3. ASR：自动停顿、连续对话和同一真实录音评测集。
4. TTS：网络抖动播放缓冲、首音频及端到端延迟统计。
5. 智能体：安全工具规划、执行失败恢复及可追踪运行状态。
6. RAG：回答引用证据、扩充语料和评测集。
7. 用户记忆：账号完整清理、长期对话摘要。
8. 视觉：确认 MediaPipe 依赖和完整多模态融合链路。
9. 3D：先选择有可用授权的模型，再开发加载和切换；不使用之前弃用的 xiao_an.vrm。
10. 工程：Docker 实际构建启动验收和浏览器回归；需可用 Docker 环境，不将配置检查视为部署成功。

各项完成以测试和实际验收为依据，不以已有模块文件作为完成标准。小功能分别中文提交，大功能独立分支，不直接修改 main。
